## 0. 重大说明：产品方向重定位

经多轮澄清，产品从原始的"**可解释因果模拟学习世界**"（修桥送材料、规则裁决、debugging 学习）**重定位**为：

> **神笔马良式简笔画想象力共创工具**：孩子一边画简笔画、一边和系统语音聊天，AI 用**同样的简笔画风格**让画面活起来、和孩子**一起共创**动画与故事；孩子全程可以任意再画、用聊天增删改。核心是**想象力、表达与共创的乐趣**；并在开放共创之上，有一层柔性的**成长引导核心**（支架式引导，引导而非裁决、不做评估）在玩中悄悄培养能力。

这个重定位**解决了第一轮评审就指出的根本张力**（开放创造 vs 可控因果）：明确以**想象力**为主体，用一层柔性引导提供方向，而非僵硬的因果裁决，也不是无边界乱想。

**版本演进**：v1.0 收敛验证（积木 + 规则表）→ v2.0 AI 原生因果（手绘 + LLM 生成规则固化）→ v3.0 神笔马良简笔画共创 → **v3.1（在线语音 + 可插拔豆包 + 成长引导核心）**。

## 2. 产品愿景（神笔马良）

### 2.1 核心体验循环（一拍）

```text
1. 孩子画一个简笔画（一匹马），或语音说"我画了一匹会飞的马"
2. 多模态 LLM 看画布 + 听语音 → 理解（这是马，孩子想让它飞）
3. 成长引导核心：判断此刻的引导机会（如引导描述细节，或问"飞去哪儿"延展想象）
4. 不清楚就语音问；AI 用简笔画补画元素（云、太阳）+ 让马飞起来 + 语音讲故事（自然融入引导）
5. 孩子看到动画 + 听到故事
6. 孩子继续：再画一条龙 / 说"让小马和云朵说话" / "把太阳改成月亮"
7. AI 增量更新画面、动画、故事
8. 循环——开放、可增删改、永不"结束"
```

### 2.2 关键洞察：简笔画作为统一视觉语言

孩子画简笔画，**AI 画的也是简笔画**：二者平等、同源、和谐，不被精美 AI 图碾压；与 tldraw + rough.js 手绘风天然一致；成本低、延迟低、可控、可编辑、可动画化（无需视频生成）。

### 2.3 共创原则

- **孩子主导，AI 伴随**：AI 是共创伙伴，不替孩子创作；孩子随时可推翻、增删改。
- **开放循环**：没有关卡、通关、正确答案。
- **语音为主**：6–10 岁孩子语音 > 打字。
- **引导而非裁决**：成长引导核心只启发，不判断对错，孩子可忽略。

## 3. 核心设计决策

### D1：全程统一简笔画风格

- 孩子用 tldraw draw / 基本图形画简笔画。
- **AI 生成简笔画 = LLM 输出 tldraw 图形指令**（draw 笔画、geo/line 等基本形状组合），渲染在同一画布、同一风格；用 rough.js / perfect-freehand 强化手绘感。
- 不引入视频 / 精美图像生成模型。

### D2：手绘 + 全程语音双向共创（在线语音）

- **在线语音模型**：STT（听孩子说）+ TTS（讲故事 / 回应 / 追问），中文识别与自然度优先。浏览器 Web Speech 方案放弃；本地 Piper+Whisper 作为进阶可选（离线、可训专属讲故事声）。
- 多轮对话：理解不足主动语音问孩子，绝不靠猜。
- **概念澄清**：语音只是"耳朵和嘴"；故事的无限想象由多模态 LLM + 开放循环保证，与语音引擎无关。

### D3：AI 让简笔画"活"起来 + 生成简笔画

- **激活**：用 tldraw Editor API 驱动图形做动画——平移、旋转、缩放、出现/消失、沿路径移动。第一阶段以简单 2D 变换 + 路径为主，配合故事旁白，足以表达"飞""走""跳""变"。
- **生成**：AI 按需添加简笔画元素（角色 / 场景 / 道具），风格统一。
- LLM 输出**结构化动画脚本**（哪些图形、何时、怎么动）驱动 Editor API。

### D4：故事共创的增量循环（增删改）

- 状态 = 画布（tldraw store）+ 故事时间线 + 对话历史。
- 每次孩子输入（画 / 说）→ LLM 产出**增量更新**（新增/修改图形、追加/改写故事、动画脚本、语音回应、引导意图）。
- 支持增删改："去掉太阳""把马变成蓝色""刚才那段重讲"都是对状态的增量操作。

### D5：多模态 LLM 职责（可插拔，默认豆包）

- **可插拔接口**，默认接入豆包 `doubao-seed-2-pro`，换模型只改配置（后端统一抽象）。
- LLM 负责：手绘 + 语音**语义理解**、**多轮澄清**、**简笔画生成指令**、动画**编排**、故事**共创**、**成长引导**（见 D6）、基本安全检查。结构化输出贯穿。
- 每拍结构化输出：

```ts
type CocreateResponse = {
  understanding: string                 // 对当前画布+话语的理解
  guidanceIntent?: {                     // 成长引导核心：本拍引导意图（D6）
    dimension: 'observe_express' | 'narrative_logic' | 'imagination' | 'problem_solving'
    move: string                         // 怎么引导（融入对话/故事，非独立任务）
  }
  askChild?: string                      // 不清楚时的一句语音追问
  addShapes?: SketchShapeSpec[]          // 要新增的简笔画（tldraw 图形指令）
  modifyShapes?: ShapePatch[]            // 要修改/删除的图形
  animation?: AnimationStep[]            // 动画脚本（驱动 Editor API）
  story?: { append?: string; rewrite?: { from: number; text: string } }
  speak: string                          // TTS 要说的话（旁白/回应，已融入引导）
}
```

### D6：成长引导核心（支架式引导）

- **定位**：教育学的**支架式引导（scaffolding）**——在孩子"踮踮脚够得到"的地方轻轻托一把，把想象 / 表达 / 思考推高一点点。**引导而非裁决，不判断对错，孩子可忽略，不打断玩兴**。呼应 Papert：微世界需要柔性引导边界，纯放养价值有限。
- **四项能力维度**：
  1. `observe_express` 观察、表达与命名（描述、命名、丰富细节）。
  2. `narrative_logic` 叙事逻辑与前因后果（叙事因果，非物理因果）。
  3. `imagination` 想象延展与发散联想（"如果……会怎样"）。
  4. `problem_solving` 创造性解决问题（故事里的温和小挑战）。
- **介入强度：均衡**——以孩子的玩为主，规律性地适时穿插启发；不放养、不喧宾夺主、不每拍打断。可用简单节奏控制（如非每拍引导、轮换维度避免重复）。
- **实现**：由多模态 LLM 驱动（系统提示扮演"懂儿童发展的启发式伙伴"），用四维度框定方向，输出 `guidanceIntent`，由共创层把它**融入** `speak` 与 `story`，而非生成独立"学习任务"。

## 4. 优化后架构（v3.1）

```text
画布层    tldraw —— 孩子画简笔画 + AI 用同风格图形作画（同一 store）；rough.js 手绘感
   │
理解层    多模态 LLM（可插拔，默认豆包）：看画布图像 + 在线语音转写 + 多轮澄清
   │
引导层    成长引导核心：判断此刻引导哪个能力维度（均衡强度）→ guidanceIntent
   │
共创层    LLM 结构化输出 CocreateResponse（增量：图形/动画/故事/语音/引导）
   │
表现层    tldraw Editor API 驱动动画 + 在线 TTS 讲故事
   │
状态      中心 store：画布(tldraw) + 故事时间线 + 对话历史（增量更新，开放循环）
   │
后端      轻量代理：统一封装多模态 + 语音（可插拔），保护各模型 key
存储      Dexie：保存创作（画、故事、动画时间线、对话）
```

**为何没有严格状态机**：神笔马良是**开放共创循环**而非有限流程，不存在"非法状态转移"要防，不需要 XState；中心 store + 增量更新即可。

## 5. 技术选型（v3.1 最终）

| 技术 | 决定 | 理由 |
| --- | --- | --- |
| **tldraw** | 核心保留 | 孩子画 + AI 画同源；Editor API 驱动动画 |
| **rough.js / perfect-freehand** | 增强 | 统一手绘简笔画质感，补 tldraw 偏精致 |
| **多模态 LLM** | 核心，**可插拔默认豆包 `doubao-seed-2-pro`** | 看画 + 对话 + 生成 + 编排 + 引导 |
| **在线语音 STT/TTS** | 核心 | 中文识别与自然度优先（替代浏览器 Web Speech） |
| **成长引导核心** | 新增（LLM 驱动 + 维度框架） | 支架式能力引导，均衡强度 |
| **Dexie** | 保留 | 保存/回看创作 |
| **轻量后端代理** | 新增（简单） | 统一封装可插拔模型，保护 key |
| **sketch-rnn / Animated Drawings / 本地 Piper+Whisper** | 进阶可选 | 地道简笔画 / 人形骨骼动画 / 离线语音 |
| **json-rules-engine、XState** | 删除 | 无因果裁决、开放循环非有限流程 |
| 视频/精美图像生成、capability/affordance/规则/修桥 | 不用 / 删除 | 旧因果方向内核 |

## 6. 里程碑

| 里程碑 | 交付 | 验收 |
| --- | --- | --- |
| **M1 画布 + 在线语音骨架** | tldraw draw + 在线 STT/TTS + 模型代理后端 | 孩子能画、能与系统语音一来一回 |
| **M2 多模态理解 + 追问** | 看画 + 听语音 → 理解（默认豆包），不清楚就问 | 系统能说出"你画的是什么、想干什么" |
| **M3 AI 生成简笔画** | LLM 输出 tldraw 图形指令（+rough.js） | AI 添加的元素与孩子的画风格一致 |
| **M4 让画面动起来** | Editor API 动画脚本 + TTS 旁白 | 孩子画的马能"飞"，伴随语音故事 |
| **M5 成长引导核心** | 四维度 + 均衡策略，引导融入对话与故事 | 引导自然、适时、不打断；孩子愿意多想一步 |
| **M6 故事共创增量循环** | 增删改：再画 / 改色 / 去元素 / 改剧情 | 孩子任意增删改，画面与故事同步更新 |
| **M7 保存与回看** | Dexie 存创作，可继续 / 回看 | 关掉再开能接着玩、能回看旧故事 |
| **M8（进阶）生动化** | sketch-rnn / Animated Drawings / 本地语音择优叠加 | 人形角色更生动、语音更亲切 |

## 7. 风险与取舍

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 成长引导核心打扰想象 | 中 | 均衡强度 + 引导可忽略 + 融入故事而非独立任务 |
| 多模态识别儿童涂鸦不准 | 中 | 全程语音多轮澄清兜底，不靠猜 |
| 动画表现力有限 | 中 | 简单 2D 变换 + 路径 + 旁白足以表达；人形用 Animated Drawings 增强 |
| LLM 生成简笔画指令质量 | 中 | 约束为有限图形原语 + rough.js 手绘化 + 风格示例 |
| 每拍 LLM / 语音延迟 | 中 | 即时画面反馈 + "AI 正在想/画"动效；非阻塞 |
| 可插拔模型接口差异 | 低 | 后端统一抽象层，隔离厂商差异 |

## 8. 验收标准

- 一名 7 岁孩子能在**无大人帮助**下：画一个简笔画 → **全程用语音**和系统聊它 → 看到它**动起来** + 听到 AI 讲的故事 → 再画 / 再说去**增删改** → 画面和故事跟着变。
- 全程**无需打字、无英文术语**。
- AI 生成的简笔画与孩子的画**风格统一**。
- 成长引导**自然、适时、不打断**，孩子在玩中愿意多描述、多想一步、给故事加因果。
- 创作可**保存、回看、继续**。
