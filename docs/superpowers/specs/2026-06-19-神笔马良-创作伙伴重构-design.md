# 神笔马良 · 创作伙伴重构 — 设计文档

> 日期：2026-06-19 ｜ 分支：`feat/magic-brush` ｜ 状态：待评审
> 一句话：把产品从"AI 多模态生成器（替孩子画、演、讲）"彻底重构为"**支架式创作伙伴**"——AI 用循证的对话式引导（PEER/CROWD）最大化**孩子自己**的想象与表达，把动画/作画降级为"孩子明确指定后的偶发兑现"。
> 立场：本设计否定本仓库此前的 AI 几何作画与分镜坐标编排。基于第一性原理（目标＝培养孩子的想象力与能力，而非取悦/炫技）与全网循证最佳实践。

---

## 1. 目标与第一性原理

**真实目标**：充分发挥 6–10 岁孩子的想象力，培养四项能力——观察表达、叙事逻辑、想象发散、创造性解决问题。**不是**"让孩子看 AI 表演"。

**不可再分的判断**：能力与想象只能靠孩子**自己生成**来长，不能靠**接收**。AI 替他想/画/讲＝认知外包，AI 越流畅，孩子动脑越少。因此：

> **系统的发动机必须是"让孩子多产出、被多拉伸一步"，AI 的输出主要是问题与支架，而不是成品。**

**现有系统为何错**（已被代码与实测证实，详见 [第一性原理-系统重构方案](../../第一性原理-系统重构方案.md)）：AI 活在像素＋自有坐标系，替孩子生成画面/故事/动画；孩子是观众。方向与目标相反。

---

## 2. 循证地基（全网最佳实践，本设计的骨架）

不自创框架，建立在被反复验证的方法上：

### 2.1 对话式共读 Dialogic Reading —— 引导引擎的骨架
成人通过提问让孩子成为"讲述者"，循证可提升词汇、叙事与想象（[Reading Rockets](https://www.readingrockets.org/topics/comprehension/articles/dialogic-reading-having-conversation-about-books)、[Famly](https://www.famly.co/us/blog/dialogic-reading-early-childhood)、[PMC 综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC4422048/)）。两个核心：

- **PEER 循环（一拍的结构）**：**P**rompt 提问 → **E**valuate 肯定回应 → **E**xpand 在孩子的话上**扩展一小步**（示范更丰富的说法）→ **R**epeat 邀请孩子用扩展后的说法再说一次。
  > **Expand 是关键**：AI 不替孩子生成，而是把**孩子自己说的**往前推一格（孩子说"小猫飞"→AI："飞过了什么呀？——飞过了高高的大山！你来说说看？"）。这正是维果茨基最近发展区（ZPD）的支架，是"培养"发生的地方。
- **CROWD 提问法（提问的五种类型）**：**C**ompletion 填空、**R**ecall 回忆、**O**pen-ended 开放、**W**h- 何人/何物/何地/为何/如何、**D**istancing 联系孩子自己的生活经验。

### 2.2 Socratic AI 守则 —— LLM 的硬约束
（[AIED 2025](https://sites.manchester.ac.uk/humteachlearn/2026/01/08/aied-2025/)、[SocraticAI arXiv](https://arxiv.org/abs/2512.03501)）：只问不直接给答案；**先给提示再给答案**；留反思停顿；孩子**始终是主动方**；按孩子水平自适应节奏。LLM 先例：[StoryPal](https://dl.acm.org/doi/10.1145/3713043.3728867)（LLM 支持的儿童对话式共读）、[ContextQ](https://arxiv.org/pdf/2405.03889)（为亲子共读生成有意义的问题）。

### 2.3 四能力维度 ← 映射到 CROWD（目标 ← 机制）
四维度是**发展目标**，CROWD/PEER 是**被验证的手段**。映射：

| 能力维度（目标） | 主用 CROWD 提问 | 示例 |
|---|---|---|
| observe_express 观察表达 | Open-ended + Wh- | "这个圆圆的是它的什么呀？还有哪儿？" |
| narrative_logic 叙事逻辑 | Recall + Completion + Wh-(为什么/然后) | "它怎么会在这儿的？然后呢？" |
| imagination 想象发散 | Open-ended + Distancing | "要是它有个超能力会是啥？你想不想也有？" |
| problem_solving 解决问题 | Wh-(怎么办) + Completion | "呀，前面一条大河——它怎么过去？" |

引导引擎按"均衡轮换"选目标维度，再选一个 CROWD 动作，套 PEER 执行（尤其 Expand）。

## 3. 系统架构（重构后）

```
画布层   tldraw —— 只有孩子的笔触。AI 不在画布上添加几何造物。
感知     qwen-vl 多模态：看画 + 听语音，产出"看到了什么"（用于反映，不下定义）
引导引擎 ★系统中心★：PEER 循环 + CROWD 提问 + 四维度均衡轮换 → 生成"激发"
兑现层   降级的动画：仅当孩子明确指令时，把孩子真实笔触做整体木偶动作（本地几何，复用 tween 内核）；豪华档可选 Meta AnimatedDrawings
语音     qwen STT/TTS（先沿用，主回路变轻后延迟可接受；流式留后续）
状态     中心 store：孩子产出信号 + 引导维度历史 + 对话历史
持久化   Dexie（保留）
```

### 3.1 一拍的主回路（能量来自孩子，结构＝PEER）
1. 孩子画 / 说。
2. **感知**：当画布自上一拍有变化时才发图给 qwen-vl（纯说话拍不重复发图，省延迟/额度）→ "我注意到……"（具体细节，**不命名、不下定义**）。
3. **引导引擎**：选本拍目标维度（轮换）＋一个 CROWD 动作 →
   - **P** 提问/挑战/火花（一句，口语、温暖、适龄）。
   - 若孩子上一拍有回答：先 **E**valuate 肯定 → **E**xpand 把他的话推进一格 → **R**epeat 邀请他再说一次。
4. 孩子回应（画更多 / 说更多）—— **锻炼在此发生**，记为"产出信号"。
5. **偶发兑现（奖赏）**：仅当孩子**明确**要某动作（"让它飞""变大"），引导引擎产出 `fulfill`，兑现层把**孩子自己的笔触**实现成该动作，作为黄金圈；随后把结果当新素材回到第 2 步。

### 3.2 LLM 新契约（无坐标、不替画、不替写故事）
```ts
type PartnerResponse = {
  noticed: string                 // 看到的具体细节，仅用于反映，禁止下定义/命名
  dimension: GuidanceDimension    // 本拍目标能力维度
  crowd: 'completion'|'recall'|'open'|'wh'|'distancing'  // 选用的提问类型
  peer: { evaluate?: string; expand?: string }           // 对孩子上一拍的肯定与"推进一格"
  provoke: string                 // 对孩子说的那句激发（P）
  fulfill: null | { behavior: 'fly'|'grow'|'spin'|'hop'|'walk'|'bounce'|'wobble'; trigger: string }
  childSignal: string             // 本拍孩子产出了什么（度量用）
}
```
**硬约束（写入 system prompt 并由 sanitizer 兜底）**：禁止输出坐标；禁止替孩子命名造物（noticed 只描述形状/颜色/位置关系）；禁止替孩子写故事情节（故事必须由孩子在 Repeat 中说出）；`fulfill` 仅当孩子明确指定动作时非空。

### 3.3 兑现层（降级的动画，两档）
- **轻量档（默认，必做，零依赖）**：把孩子当前全部笔触作为一个整体 rig，本地行为词表 fly/grow/spin/hop/walk/bounce/wobble，复用现有 [playScenes.ts](../../src/animation/playScenes.ts) 的 EASES/tween/缓动内核，操作真实 tldraw shape，无 AI 坐标。
- **豪华档（可选，P3）**：[Meta AnimatedDrawings](https://github.com/facebookresearch/AnimatedDrawings)（开源）把孩子画的人物自动绑骨、做走/跳/舞。需独立 Python 服务（detectron2/TorchServe），偏人形。**仅家庭自用、非商业，许可与场景合适**。作为可选增强，不进主链。
- idle 微动（[idle.ts](../../src/animation/idle.ts)）保留作"活着"底噪，但**克制**，不喧宾夺主。

## 4. 取舍清单（不怕废弃）

| 现有资产 | 处置 | 理由 |
|---|---|---|
| AI `addShapes` 几何作画 + 坐标 | **废弃** | 认知外包 + 坐标幻觉 + 风格伪命题的根源 |
| LLM 分镜坐标/路径编排（`ActorAction.x/y/path`，作主回路） | **废弃** | 同上；保留 tween/缓动/`pointAtT` 内核给兑现层复用 |
| AI 写整段故事 / 替孩子命名 | **废弃** | 直接违背"孩子自己生成"的目标 |
| 成长引导核心（仅 prompt 一句） | **升级为系统中心** | 重写为 PEER+CROWD 引导引擎 + 四维轮换 |
| `SketchShapeSpec` / `CocreateResponse` | **重构** | 改为 `PartnerResponse`（无坐标、引导为中心） |
| 把孩子笔触纳入"可动模型" | **新建** | 兑现层核心，当前完全缺失 |
| tween/缓动/RAF 内核、idle | **保留复用** | 作用在真实 shape，方向正确 |
| qwen 语音、Dexie、sanitizer、ESLint、tldraw、工程 | **保留** | 干净底座，与根因无关 |
| 串行 12s 重回路 | **自然消解** | 主回路变轻对话；重生成只在偶发兑现 |

> 净效果：**删多于加**，复杂度下降，且第一次对准真实目标。

## 5. 模块边界（可独立测试）

- `guidance/engine.ts`（纯函数）：输入 {四维历史, 上一拍孩子信号}，输出 {目标维度, CROWD 类型, PEER 提示}。无 I/O，纯策略，单测覆盖轮换/均衡/不重复。
- `server/partnerPrompt.ts` + `callPartner()`：组装 system prompt（PEER/CROWD/Socratic 守则 + 硬约束）+ 感知，调 qwen-vl，sanitize 成 `PartnerResponse`，失败重试一次。
- `fulfill/behaviors.ts`（纯几何 + 引擎）：行为词表 → 对一组真实 shape 的整体变换脚本；复用 tween。单测覆盖每个行为的位姿计算。
- `store/sessionStore.ts`：记录 childSignal、dimension 历史、对话；persist 不变。
- `App.tsx`：编排——感知→引导→（孩子回应）→偶发兑现；UI 极简（孩子画 + 说话 + AI 一句话 + 偶尔动起来）。

## 6. 度量与验收（替代"功能清零"）

**产出信号（每拍记录，本地）**：孩子是否回应、说了几个词/画了几笔、是否答上激发、是否在 Repeat 中用了更丰富的说法、是否自己解决了那道小坎。

**核心验收**：一名 7 岁孩子无大人帮助，能在引导下**越说越多、越画越多**；至少出现一次"被一个'如果…会怎样'问得想出新点子"；至少一次"自己想办法解决 AI 出的小难题"；偶发兑现时露出"这是**我**让它动的"的成就感（而非"AI 真厉害"）。

**反模式守门（必须避免）**：AI 替孩子命名/写故事/给现成答案；每拍都引导（要有留白）；兑现变成每拍主菜；孩子变回观众。

## 7. 分阶段落地

**P0 —— 引导引擎 + 主回路（最高价值，先做）**
- `guidance/engine.ts`（PEER/CROWD/四维轮换，纯函数 TDD）。
- `callPartner()` 新契约 + system prompt（PEER/CROWD/Socratic 硬约束）+ sanitizer。
- App 主回路：感知→激发→孩子回应；语音沿用 qwen；UI 收敛为"孩子画 + 一句激发 + 轻对话"。
- **废弃** AI 几何作画与分镜坐标主链。
- 验收：孩子画个东西，AI 不替他命名、而是问出一句让他**想多说**的话；多拍维度均衡轮换。

**P1 —— 兑现层（轻量档）**
- `fulfill/behaviors.ts`：把孩子真实笔触整体做 fly/grow/spin/hop/walk/bounce；仅 `fulfill` 非空时触发。
- 验收：孩子说"让它飞"，**他自己画的**东西飞过屏幕；其余拍以引导为主。

**P2 —— 度量与节奏打磨**
- 产出信号记录与轻量可视（给家长/自己看"今天孩子说了多少、想出了什么"）；引导节奏自适应（孩子卡住就降难度/换维度）。

**P3 —— 豪华兑现（可选）**
- 接 Meta AnimatedDrawings（独立 Python 服务）做人物绑骨走/跳；仅在孩子画了人形且明确要时。评估后再投。

## 8. 风险与诚实判断

- **最大风险是产品假设本身**：孩子是否因"被好好提问"而更想创作？P0 即用于最便宜地验证——若孩子在引导下产出明显变多，假设成立。
- **感知延迟**：qwen-vl 看画仍有数秒；但主回路是"一句问题"，可用"嗯，我看看哦～"填充，远比"等 12 秒看动画"可接受。流式语音（qwen 实时）留 P2+。
- **LLM 越界**：模型可能忍不住替孩子命名/写故事 → system prompt 硬约束 + sanitizer 过滤 + 度量反模式守门三重防。
- **AnimatedDrawings 重**：Python 服务 + 人形限定，列为可选 P3，不进主链，避免拖累家用部署。
- **过度说教**：要有留白与乐趣（兑现奖赏、温暖口吻），否则低龄孩子流失——靠"激发为主 + 偶发兑现"的天平把控。

---

## 9. 一句话
把系统的发动机从"AI 生成"换成"孩子生成、AI 用 PEER/CROWD 把他往前推一格"。这才对准你的真实目标，并顺带消解了延迟、坐标、风格三大老问题。**先做 P0 的引导引擎，用一个真孩子验证"被好好提问会不会让他创作得更多"。**
