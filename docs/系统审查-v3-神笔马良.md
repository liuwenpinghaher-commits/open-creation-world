### 🔴 P1-3 · CONFIRMED · [E/H 两维发现]｜`saveNow` 对 async 用 `try{ void saveWork() }catch` 是无效防护 → IndexedDB 写失败逃逸为未处理拒绝、连 `console.warn` 都不打印、更无 UI 信号 → 孩子的画静默丢失
- **file**：[src/App.tsx:99-103](../src/App.tsx#L99-L103)（存盘调用点 150/185/307，读盘 113/182，`main.tsx:5` 佐证）
- **失败场景**：IndexedDB 写入持续失败（配额耗尽 `QuotaExceededError` / Safari 隐私模式 IDB 不可用 / 存储压力被驱逐）。孩子边画边聊，`store.listen` 每秒调 `saveNow` → `void saveWork(...)`。`saveWork` 是 async，`try/catch` 只能抓**同步**抛出（该行唯一同步项是 `editor.getSnapshot()`）；`db.works.put()` 的 reject 发生在 async 内部，只让 `saveWork` 返回的 promise 拒绝，**永不进这个 catch**——注释承诺的 `console.warn('save failed')` 是死代码。UI 上也无任何 serviceError/hint。孩子画半小时，刷新后自上次成功保存以来的全部笔触与对话丢失，家长毫不知情。
- **复现**：mock `db.works.put` 返回 rejected promise，调 `saveNow()`：观察 catch 不触发、无 `console.warn`；`main.tsx` 只注册 `'error'` 监听、无 `'unhandledrejection'` 处理器 → 静默。
- **根因**：对 async 函数用 `try{void f()}catch` 无效（async 从不同步抛出，异常一律进 returned promise）；既无 `.catch` 兜底，也无全局 `unhandledrejection`，更无面向家长的"保存失败"可见状态——fail-safe 退化成 fail-silent。
- **修复**：`saveWork(...).catch(err => { console.warn('save failed:', err); setSaveError(true) })`；新增 `saveError` state 渲染成类似 `serviceError` 的醒目条（"刚才没存上，点我重试"），下次成功保存清除；同时给 `openWork`/`removeWork`/`autoStory` 的 void 异步补 `.catch`，并在 `main.tsx` 注册全局 `unhandledrejection` 兜底日志。
- **影响面**：任何 IndexedDB 写受阻的浏览器环境下的静默数据丢失——本项目"数据能不能信"的底线。
- **反驳与回应**：反驳——桌面 Chrome 下 IDB 极少失败，是否边角？回应——Safari 隐私模式、移动端配额、长会话大快照（tldraw snapshot 可观）都会触发；且"无信号"本身是缺陷（对比 partner 失败有诊断条）。属 fail-silent，非 fail-safe。
