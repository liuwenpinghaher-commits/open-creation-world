# 神笔马良 · 第一性原理重构方案

> 日期：2026-06-19 ｜ 性质：架构判决 + 最优方案，不怕重构、不怕废弃已实现功能。
> 立场：本文否定包括我此前所写（分镜引擎、AI 坐标作画）在内的设计。结论基于代码与实测证据，非印象。

---

## 0. 方法：先回到不可再分的目标

把产品口号、PRD、已写代码全部清空，只问一句：**一个 6 岁、可能还不识字的孩子，坐在屏幕前，怎样会"哇"出来、并且一画再画？**

拆到不能再拆，只剩三条硬约束：
1. **即时**：孩子做一个动作（画一笔 / 说一句），**1–2 秒内**必须有回应。儿童注意力窗口以秒计。
2. **是"我的"**：让他惊喜的必须是**他自己画的东西**活过来——神笔马良的典故是"马良画的画变成真的"，不是"另一个人在旁边替他画"。
3. **可继续**：每次回应都要留一个"接下来呢"的钩子，让循环转下去。

任何架构，先用这三条量它。下面就量当前系统。

## 1. 对当前系统的判决（可行性 / 可用性）

**结论先行：当前架构在三条硬约束上全部不达标，且根因是结构性的，靠继续打补丁无法解决。** 它能跑通一次 demo（E2E 已证明机制可用），但跑不出产品。

### 致命缺陷 A —— AI 根本不知道孩子画了什么（结构性）

证据（代码级，已核验）：
- 发给 AI 的"画布已有元素清单"只来自 `session.shapes`（[buildRequest.ts](../src/cocreate/buildRequest.ts)）。
- 而 `session.shapes` **只装 AI 自己 `addShapes` 的图形**（[sessionStore.ts:20-26](../src/store/sessionStore.ts#L20)，`applyResponse` 只 push `res.addShapes`）。
- 孩子用画笔画的 tldraw 笔触，**永远不进这个清单**。AI 对它们**没有任何 id、没有任何结构**，只能从一张拍扁的 PNG 像素里猜（[App.tsx:127](../src/App.tsx#L127) `toImageDataUrl`）。

**推论**：AI 永远无法引用、移动、动画化孩子自己画的任何一笔。所谓"让画面动起来"，动的全是 AI 另起炉灶、在 0..1 坐标里凭空摆出来的几何图形，**和孩子的画各画各的**。硬约束 2（"是我的"）从架构上就不成立——这是最致命的一条。

### 致命缺陷 B —— AI 在它最不擅长的维度上被迫硬编坐标

当前每拍要 LLM 一次性吐出：图形的归一化坐标、分镜里每个动作的目标坐标/路径（[ActorAction.x/y/path](../src/types/cocreate.ts)）。LLM 看到的是一张它只瞥了一眼的 PNG，却要回报精确像素位置。**LLM 在精确空间推理上恰恰最弱**。结果：新元素位置随机、比例失调、动画把东西甩到空白处或互相穿插。而且**没有任何闭环**去校正——发出去就完。我加的 sanitizer/重试只能保证 JSON 合法，保证不了坐标合理（业界共识：schema 合规 ≠ 语义正确）。

### 致命缺陷 C —— 延迟比可用门槛高一个数量级

实测（`npm run test:real`）：**单次多模态调用 12.7 秒**，三拍共创 26.9 秒。儿童可用的反馈窗口是 1–2 秒。**12 秒等待对 6 岁孩子是灾难性的**，"✨我在想…"浮层只是给灾难涂口红。这不是优化项，是架构选择（每拍都串行走"录音→上传→STT→大模型→渲染→TTS→下载→播放"）导致的必然结果。

### 致命缺陷 D —— 风格统一是个伪命题（按当前路线无法成立）

孩子画的猫＝几笔手势化的自由笔触；AI 的猫＝[圆头＋椭圆身＋两条线腿]的**参数化几何拼装**。`dash:'draw'` 只是描边抖动，改变不了"手势笔触 vs 几何拼装"是两种本体。**用 ellipse/rectangle/line 原语永远拼不出和孩子同源的画**。我上一轮说"已统一风格"——那是逢迎，不成立。

### 缺陷 E —— 单次 LLM 调用承担了过多角色

一次 JSON 要同时做：视觉理解＋语音意图＋成长引导决策＋作画＋多分镜编舞＋写故事＋说话。等于让一个非前沿模型同时当视觉系统＋导演＋动画师＋编剧＋老师。每个轴都平庸，且最脆的（坐标/动画）正是产品卖点所在。

### 旁证：需求反复横跳本身是信号

动画需求从"重分镜引擎"→"太重，只要过程动画"→"还是分镜引擎"来回摆。这说明**动画形态的价值没被想清楚**——因为大家潜意识里都感觉到：动的不是孩子的画，再炫也不对。

---

## 2. 单一根因

> **系统没有一个"孩子真实画作"的共享模型。AI 活在像素 + 自己另开的坐标系里，与画布上真正存在的笔触是两套互不相通的世界。**

缺陷 A/B/D/E 都从这里长出来。不解决这个根，分镜引擎、idle、校验、持久化做得再精致，都是在错误地基上盖楼。

---

## 3. 从第一性原理重新推导最优架构

### 3.1 产品重定义（这是最大的一刀）

**把"AI 在孩子旁边一起画"彻底废弃，改成"神笔马良"的字面意思：让孩子自己画的那幅画，动起来、活过来、并被讲成故事。**

马良画的画变成真龙——不是另一个人替他画龙。对应到产品：
- 画布上**只有孩子的笔触**。AI **不在画布上添加几何造物**。
- AI 的职责变成：**理解这幅画是什么 → 让这幅画（孩子的真实笔触）动起来 → 配上声音和故事 → 给一个"接下来"。**

这一刀同时干掉 A、B、D 三个致命缺陷：
- 不再需要 AI 知道坐标——动的是**已存在的真实 shape**，位置我们本来就有（tldraw 给）。
- 不再有风格冲突——画布上从头到尾只有孩子的画。
- "我的画动了"的魔法**第一次真正落地**。

### 3.2 用"延迟"把系统切成三个解耦的回路

不要再用一个 12 秒的串行大回路。按反馈速度分层：

| 回路 | 触发 | 时延预算 | 干什么 | 靠谁 |
|---|---|---|---|---|
| **即时回路** | 孩子说常见指令/画一笔 | **< 150ms** | 把孩子的画当"木偶"立刻做动作：飞、跳、变大、转圈、跑过去、抖一抖 | **纯本地**，关键词→行为，零网络 |
| **语音回路** | 说话 | ~1s 感知 | 边说边转写、边出声 | **流式** STT/TTS（qwen 实时 WebSocket） |
| **理解回路** | 每拍 | 后台 3–10s，**不阻塞** | 看画→理解"这是什么"、写故事、想引导、提出新点子 | 大模型，**异步增强**，好了再叠加 |

核心原则：**孩子永远不等大模型。** 即时回路先给反馈（画动了 + 一句本地话），理解回路在后台把故事/更丰富的演出补上。

### 3.3 把孩子的画变成"可动的木偶"（技术核心）

- **粗粒度 MVP（高确定性、必做）**：把孩子当前所有笔触作为一个整体 rig，做整体行为——平移飞过画面、原地跳、放大缩小、旋转、弹跳、抖动、沿路径走。**全部基于真实 shape，本地计算，零 LLM 坐标。** 这已经能交付"我的画动了"的核心魔法。
- **细粒度（进阶、可选）**：要让"腿走路/翅膀扇动"，需要把笔触分组（哪些笔是腿）。自由笔触分割是真难题。务实解：**让孩子点一下**"这是它的腿吗？"（点选即分组），或用大模型视觉回**区域框**、我们把框内的笔触归一组。**不靠 LLM 给坐标，只靠它给语义分组提示，几何仍本地解析。**

### 3.4 LLM 的新契约：只给意图，不给坐标

LLM 输出从"图形坐标＋关键帧"改成：
```
{ "is": "一只在天上的小鸟",            // 对画的理解（喂给故事/引导）
  "behavior": "fly_across",            // 从固定行为词表里选一个
  "target": "top-right",               // 语义锚点，engine 本地解析成坐标
  "mood": "happy",
  "story": "小鸟扑棱着翅膀飞过云朵。",
  "say": "你的小鸟飞起来啦！要不要给它找个朋友？",
  "guide": { "dim": "imagination", ... } }
```
engine 拿 `behavior + target`，结合**画布上真实 shape 的真实包围盒**，本地算出运动。LLM 干它擅长的（理解、命名、叙事、选意图），engine 干它擅长的（几何）。**这是把脆弱性从系统里彻底移除的关键。**

### 3.5 风格问题的诚实答案

放弃"AI 画得和孩子一样"。**AI 不画线，改用孩子的画做不到的、与之互补的语言**让画活起来：运动、节奏、淡入的颜色光晕、影子、表情高光、偶尔一个**确定性摆放**的小伙伴（不是 LLM 给坐标，而是 engine 放在某个真实 shape 旁边）。孩子的线条神圣不动，AI 让它"演"。这比假装同源更诚实、更可行，也更像神笔马良。

## 4. 取舍清单（不怕废弃）

| 现有资产 | 处置 | 理由 |
|---|---|---|
| AI `addShapes` 几何作画 + 坐标 | **废弃** | 致命缺陷 A/B/D 的来源 |
| 分镜引擎里 LLM 编排的坐标/路径关键帧 | **废弃/改造** | 改成"行为词表 + 本地几何解析"；保留 tween/缓动/RAF 内核（[playScenes.ts](../src/animation/playScenes.ts) 的 EASES/pointAtT/tween 可复用） |
| `SketchShapeSpec` / `ActorAction.x/y/path` | **重构** | 改为 behavior/target/anchor 语义模型 |
| 把孩子笔触纳入"可动模型" | **新建（核心）** | 当前完全缺失，是魔法所在 |
| idle 微动画 | **保留** | 它本就作用在真实 shape 上，方向正确，是"活着"层的雏形 |
| 串行 12s 语音→大模型回路 | **拆解** | 即时/语音/理解三回路解耦 + 流式 |
| 本地校验/重试 sanitizer | **保留并收窄** | 新契约字段更少更稳，仍需兜底 |
| Dexie 持久化 / 错误兜底 / ESLint | **保留** | 与根因无关，是干净底座 |
| tldraw / Vite / React / 工程结构 | **保留** | 没问题 |

> 估算：废弃的代码量 > 新增。这是**净简化**，不是堆功能。

## 5. 分阶段落地（精益、每阶段可独立验证）

**P0 —— 木偶魔法 + 即时回路（最高价值、最低风险，先做）**
- 把孩子全部笔触作为整体 rig；本地行为词表：fly_across / hop / grow / spin / bounce / walkTo / wobble。
- 即时触发：常见中文指令本地关键词匹配（飞、跳、变大、转圈、跑）→ <150ms 动起来 + 本地一句话（先用浏览器 TTS 或预存音）。
- 验收：孩子画个东西、说"让它飞"，**1 秒内他自己的画飞过屏幕**。这一步就证明了核心假设。

**P1 —— 理解回路（异步）+ 故事 + 流式语音**
- 大模型后台返回 `is/behavior/target/story/say/guide`（**无坐标**）；engine 本地解析。
- 流式 STT/TTS（qwen 实时）把语音感知延迟压到 ~1s。
- 即时回路先动，理解回路回来后叠加故事旁白/更贴切的行为。

**P2 —— 细粒度 rig（可选）**
- 点选分组（"点一下它的腿"）或 LLM 区域框 → 让局部（腿/翅膀）动。仅在 P0/P1 验证产品成立后再投。

**P3 —— AI 互补表现（可选）**
- 颜色光晕、影子、确定性摆放的小伙伴。绝不回到 LLM 给坐标。

## 6. 可行性与风险（诚实）

- **P0 完全可行、低风险、高回报**：操作真实 tldraw shape 做整体变换，本地关键词匹配——纯本栈、可 Playwright 验证、零外部依赖。强烈建议立刻做，它用最小成本证伪/证实整个产品假设。
- **流式语音**：真实但有界的后端重写（qwen 实时 WebSocket 代理 + 浏览器音频流）。价值＝把 12s 降到 ~1s。风险：无麦克风环境自动化测试覆盖不到，需真机联调。
- **细粒度分割（P2）**：真难题，**不要一开始碰**。点选分组是务实退路。
- **最大风险其实是产品假设本身**：孩子是否真的因为"自己的画动了"而一画再画？所以 P0 的意义不只是功能，是**最便宜的假设验证**。

---

## 7. 怎么算成功（替代"功能做完"）

不再用"功能清单清零"当成功。用：
1. **首响延迟** < 1.5s（即时回路）；端到端故事 < 可接受等待。
2. **真机观察一个 6–8 岁孩子**：他画的东西动起来时是否"哇"；是否主动说"再…/把它变成…"；是否反复回来。
3. A/B：**"孩子的画动" vs "AI 在旁边画"**——直接验证 §3.1 的重定义是否正确。

---

## 8. 一句话

当前系统在错误的地基上盖了一座精致的楼：**AI 和孩子的画从未在同一个世界里**。最优解不是把楼盖得更高，是把地基换成"孩子自己的画就是主角"——这一刀同时解决放置、风格、魔法归属三大死结，并让延迟问题有解。**先做 P0 的木偶魔法，用一周和一个真孩子，验证这个产品到底成不成立。**
