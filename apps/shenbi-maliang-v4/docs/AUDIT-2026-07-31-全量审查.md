| # | 级 | 问题 | 影响 |

### 设计不合理 Top 3

1. **深化设计的教练环已大部分落地**，但成长册信息架构从「三屏」膨胀为 overview/works/track/prefs/weekly + 下钻，**家长认知负荷偏高**（对家庭自用可接受，但 P0 边界模糊）。  
2. **engine 优先级**把 contentHint 放在 strength 弱维之前，设计上「本地线索增强」合理，但会削弱「状态驱动提高」叙事，需在规格中显式冻结或下调。  
3. **扩展维**同时存在「启发式 recount + `ext_signal` 双写」，统计可能重复计数（`countExtHits7d`），分析口径需统一。

## 3. 设计合理性结论

### 3.1 仍然正确的冻结决策

- **V4-D1/D3/D4**：交互是传感器、证据结构化 —— 实现方向正确。  
- **V4-D5/D7**：过程热度 + 禁止排名 —— 文案与 quality 门一致。  
- **V4-D8**：不替画 —— fulfill 边界正确。  
- **V4-D13**：模块分目录 —— **目录**有 `growth/*`，但 **session/成长 UI 两文件再次 God 化**。  
- 三层 A/B/C 数据流与 v4.1 每拍事件顺序 **一致**。

### 3.2 设计/实现张力

| 点 | 评价 |
|----|------|
| P0 vs 已实现厚度 | 代码已明显超过 §10 P0；深化教练环已进主 UI，**分期叙事落后于代码** |
| engine 优先级 | sessionFocus > contentHint > preferredDimension：补缺强、状态弱维中等、内容线索强 —— **需产品确认是否故意** |
| 成长册五屏+下钻 | 对家长「看见变化」充分，但密度高；与 v4.1「P0 屏 A+简 B」相比 **过重但可用** |
| 扩展维双通道 | `ext_signal` 正式写 + report 再启发式数 said —— **有双计风险** |
| 语音仍自研直连 | 符合「先成长后换管道」；barge/VAD 代码在，真机完整度本轮未验 |

### 3.3 明确合理且应保留

- 唯一写入口 `recordPartnerTurn`（B/C 不散落 UI）。  
- 策略本地、`line` 仅润色 + `finalizePartnerLine`。  
- 家长门后成长册；画布不堆图表。  
- 处方需家长「采纳」才写 sessionFocus（人在环上）。

### 5.3 E2E 策略风险（静态）

- `03-growth` / `02-settings` / `04-navigation` / `05-demo`：**普遍 `seedAndGoto`**。

### 5.4 已知代码级缺陷（可复现于阅读）

1. **STT source 失真** — `usePartnerSession.ts` 约 428 行：  
   `source: proactive ? 'proactive' : 'type'`  
   按住说话成功后仍标 `type`。  
2. **失败不写 said** — `recordPartnerTurn` 仅在 `askPartner` 成功之后；partner 4xx/5xx 时孩子话语不进 events（dialog 亦不写）。  
3. **childStateSummary 缺失** — `askPartner` body 无状态摘要字段；仅 moveHint + childContext(档案/主题)。  
4. **衰减不落盘** — `loadDimensionStates` 返回 decay 后内存态；除非随后 `recordPartnerTurn` save，否则纯浏览成长册不持久化衰减后 strength。  
5. **ext 计数可能双计** — 既写 `ext_signal` 又对 `said` 启发式 ++。
