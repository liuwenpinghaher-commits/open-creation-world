## 1. 三仓对照（深度）

### 1.1 创造世界：载体侧「会引导的共创」

| 能力 | 做法 | 本仓继承度 | 缺口 |
|------|------|------------|------|
| 四维素质 | observe / narrative / imagination / problem | ✅ 主维一致 | — |
| 本地 engine | dimHistory + stuck + 权重 → move | ✅ 有 nextMove + pickFocus | contentHints / turnInSession / lastChildAct **未完整** |
| CROWD 问法 | 维→open/wh/recall… | ✅ playbook 有 | 家长看不见本拍 crowd |
| PEER 结构 | 肯定→扩展→问 | ⚠ 写在人设精神里 | **未结构化校验**每句是否 PEER |
| LearningStory | 作品结束叙事+高光+兴趣标签 | ❌ | 无「故事卡片」落库 |
| 成长册 | 作品流+对话+维次数 | 部分 | 有下钻/跟踪，缺故事层与缺口处方 |
| AI 元素养 | 人做主/会错/可反驳 | 类型有扩展维 | 未进状态机主路径 |

**可吸收的冻结原则（创造世界已证）：**

1. **人设 ≠ 策略 ≠ 生成**；策略主权本地。  
2. **信号增强本地**优于纯转盘与纯 LLM 选维。  
3. 成长册给家长看「共创痕迹」，不打分。

### 1.2 儿童培养工具：思维 OS「会安装的操作系统」

| 能力 | 做法 | 本仓能否硬搬 | 应如何映射 |
|------|------|--------------|------------|
| 五维 OS | 解构/推演/建模/觉察/韧性 | ❌ 不宜替换画板四维 | 上位标签：catalog 已映射 |
| L0–L4 + 红黄绿 | 行为锚点+阈值 | ⚠ 易变成成绩单 | 仅内部/家长「进阶描述」，禁止等级羞辱 |
| **支架渐退率 fadeRate** | 终极 KPI：少支架仍能完成 | ✅ 极应吸收 | 用 support high→normal 的比例定义 |
| 贝叶斯/错误层 | 题型诊断 | ❌ 画板无标准答案 | 不搬；用 engagement + 改画/纠正信号代替 |
| 协议 Protocol | YAML 多帧教学 | ❌ 过重 | 用 **PLAYBOOK 任务卡片 + 缺口配方** 轻量代替 |
| 跨载体迁移 | 多训练场同一 OS | 后期 | 先只在「画/说」两传感器内谈迁移 |
| 每日配方/补缺 | 弱 OS 选题 | ✅ 思想要 | 成长页「本周补缺」+ 写回 weights |

**可吸收的冻结原则（儿童培养）：**

1. **OS 是账本，载体是练习场**——画板是练习场，不是换 OS 名。  
2. **支架渐退 > 练习次数**——练得多但一直 high support = 未内化。  
3. **补缺是系统行为**：弱维 → 配方 → 会话目标，不是家长空想。

### 1.3 本仓现状（诚实分层）

```text
┌─ 已有 ─────────────────────────────────────────────┐
│ A 传感器：画(tldraw) + 说/听 + VL                   │
│ B 证据：events + works.dialog + sceneNote(半隐)     │
│ C 状态：四维 strength + supportBias + 扩展痕迹      │
│ 策略：engine 选维 + PLAYBOOK 文案 + 人设可配         │
│ 家长：设置全配置 + 成长下钻/跟踪/导出                 │
└────────────────────────────────────────────────────┘
┌─ 断裂（所以显得「简单」） ──────────────────────────┐
│ 1. 伙伴文案改了 ≠ 知道该补哪维（无缺口驱动文案建议）  │
│ 2. 状态更新了 ≠ 下一会话有「本周焦点」任务条          │
│ 3. 历史 dialog 在 ≠ 被梳理成 LearningStory / 主题线  │
│ 4. 有 supportBias ≠ 有支架渐退率与补缺处方            │
│ 5. 有扩展维类型 ≠ 写事件/进状态/进策略                │
│ 6. sceneNote 在跑 ≠ 家长可见/可检索的记忆中心         │
└────────────────────────────────────────────────────┘
```

**判断：** 不是 prompt 字数太少，而是 **缺少「培养操作系统」的中层**——儿童培养叫 Protocol/诊断，本仓应叫 **Growth Coach Loop（成长教练环）**。

## 2. 目标架构：成长教练环（冻结）

```text
                    ┌──────────────┐
                    │ 家长可读档案  │
                    │ 总览/缺口/故事 │
                    └──────▲───────┘
                           │ 聚合 report / story
┌──────────┐  状态+缺口   ┌┴────────────┐  move+支架   ┌──────────┐
│ 分析引擎  │────────────►│ 策略 engine │────────────►│ 伙伴 LLM  │
│ 缺口/趋势 │◄────────────│ + PLAYBOOK  │◄────────────│ 润色一句  │
└────▲─────┘  证据回写   └─────────────┘  本拍信号    └────▲─────┘
     │                                                      │
     │              ┌──────────────┐                        │
     └──────────────│ 证据与记忆 B │◄───────────────────────┘
                    │ events/works │
                    │ sceneNote    │
                    └──────────────┘
```

**一句话：** 伙伴不是聊天壳，是 **教练执行器**；成长档案不是报表，是 **教练的黑板**。

### 2.1 五层记忆（必须分清）

| 层 | 名称 | 存什么 | 谁写 | 谁读 | 家长呈现 |
|----|------|--------|------|------|----------|
| M0 | 瞬时 | 本拍 utterance / 截图 | session | LLM 本拍 | 否 |
| M1 | 会话 | history 近轮、dimHistory | session→works | 策略+LLM | 作品对话 |
| M2 | 画布语义 | sceneNote | partner noticed | 下一拍 prompt | **应可见** |
| M3 | 证据账本 | events xAPI | recordPartnerTurn | 分析/下钻 | 已有下钻 |

当前缺 **M5** 与 **M4 的处方字段**；M2 未呈现。

## 3. 维度培养：如何做（吸收两仓后的定稿）

### 3.1 双层模型（已部分落地，需用满）

| 层 | ID | 角色 | 策略是否主动选 |
|----|-----|------|----------------|
| **练习主维（画+聊）** | 四维 CORE | 每拍 move 主键 | 是 |
| **协作元认知** | 三扩展 | 过程痕迹 / 加分信号 | 否（由行为推断） |
| **思维 OS（上位）** | 解构/推演/建模/觉察/韧性 | 解释与跨产品对齐 | 否（映射标签） |

**禁止：** 用 OS 五维替换四维当画板转盘（载体不对）。  
**必须：** 家长界面同时能看到「练的是哪维」与「思维侧像哪门 OS」。

### 3.2 每维「培养单元」结构（从儿童培养 Protocol 压缩）

每个 CORE 维应有可配置、可测的培养单元：

```ts
type DimCultivationUnit = {
  id: CoreDimension
  label: string
  osMap: ThinkingOs[]           // 上位
  playbook: { goal, how, example }  // 已有，可覆盖
  /** 可观测行为锚点（过程，非分数） */
  anchors: string[]
  /** 低支架成功信号 */
  fadeSignals: string[]         // 如：无 high support 仍能多说/改画
  /** 缺口时的家长任务卡片 */
  gapTips: string[]
  /** 策略偏好 CROWD */
  crowd: CrowdType[]
}
```

与创造世界 PEER 对齐：高支架 = 半句填空/二选一；正常 = open/wh；flowing = 少问多接。

### 3.3 支架渐退（从儿童培养 fadeRate 映射）

```text
fadeRate_7d(dim) =
  count( practiced(dim) ∧ support=normal ∧ engagement≠stuck )
  / max(1, count(practiced(dim) in 7d))
```

| fadeRate | 家长话术 | 系统动作 |
|----------|----------|----------|
| 高（≥0.6） | 「这维更能自己说了」 | 可降低权重或换焦点 |
| 中 | 「还在练」 | 保持 |
| 低（≤0.35 且练习≥3） | 「这维还需要更简单的带着说」 | 抬 supportBias、补缺任务 |

**KPI 优先级：** 渐退率 > 练习次数 > strength 条。

### 3.4 缺口检测与补缺（从「每日配方」压缩）

```text
gap(dim) 当且仅当（窗内）：
  practice7d 明显低于中位  OR  fadeRate 低  OR  supportBias=high 持续
  OR 家长权重故意压低且实际为 0（需确认是否「想少练」）
```

**补缺输出（写回系统，不只文案）：**

1. `sessionFocus[]`：下 N 次会话优先维（写入 kv / prefs）  
2. 临时 `weights` 建议（可一键采纳）  
3. 一条 **本周任务卡片**（来自 gapTips + PLAYBOOK.example）  
4. 可选：人设不动，只改 PLAYBOOK.example 为更贴缺口的问法（系统建议，家长确认）

## 4. 历史如何梳理

### 4.1 三档时间粒度

| 粒度 | 对象 | 动作 |
|------|------|------|
| 拍 | turn bundle | 已有溯源 L4 |
| 作品 | work | dialog + 维统计 + **LearningStory** |
| 周/月 | child | 跟踪对比 + 缺口 + 叙事 headline |

### 4.2 LearningStory（吸收创造世界）

```ts
type LearningStory = {
  workId: string
  childId: string
  narrative: string      // 家长可读 2～4 句，禁止得分
  highlights: string[]   // 孩子金句/关键改画
  dims: CoreDimension[]  // 本作品主练
  interests?: string[]   // 检测到的主题（恐龙/月亮…）
  createdAt: number
}
```

生成时机：作品「告一段落」（新画 / 长时间无互动 / 家长点生成）。  
生成方式：P0 规则模板（维次数+dialog 摘句）；P1 可选 LLM **只写叙事不改 strength**。

### 4.3 主题线（历史梳理的第二刀）

跨作品聚类 interests / sceneNote 关键词 → 「最近三条线：恐龙宇宙 / 过河冒险 / …」。  
用于：伙伴 childContext 增强、家长「他最近在意什么」。

## 5. 如何分析成长档案

| 产物 | 内容 | 数据源 |

| 纵向跟踪 | 已有窗对比 | events |

## 7. 如何补齐缺陷（系统闭环，不是鸡汤）

```text
检测 gap
  → prescribe 生成「补缺处方」
  → 家长确认或默认采纳
  → 写入 prefs.weights / sessionFocus / 可选 PLAYBOOK.example 建议
  → 之后 N 次会话 engine 优先该维 + 合适支架
  → 新证据回流
  → gap 关闭或改写
```

**伙伴文案在闭环中的位置：**

| 角色 | 是否应用自由编辑的长人设 | 说明 |
|------|--------------------------|------|
| 语气/禁区 | ✅ 人设覆盖 | 慢变 |
| 练哪维 | ❌ 不靠改人设 | 靠 engine + focus |
| 怎么问 | ✅ PLAYBOOK | 可被补缺处方建议改 example |
| 补缺任务 | 成长页卡片 | 不塞进 system 长文 |

因此：**把培养做深 ≠ 把人设写成论文**；而是 **处方驱动策略 + 短 PLAYBOOK + 证据回流**。

## 8. 伙伴系统「不简单」的目标形态

### 8.1 现在（薄）

```text
固定/可编人设 + 可编 PLAYBOOK + 安全开关
     → 每拍 move（弱维/权重）
     → 一句 LLM
```

### 8.2 目标（厚而不乱）

```text
档案(M4+缺口) + 本画 sceneNote(M2) + 主题线
     → engine(E 信号增强): focus ∪ weights ∪ engagement ∪ contentHints
     → PLAYBOOK[维] + 支架
     → composeSystem(人设+底线+安全+孩子档案一句)
     → LLM 润色
     → 写 events + 更新状态 + 更新渐退统计
     → （作品结束）LearningStory
     → （周）缺口处方 → 回写 focus
```

配置页仍呈现：人设、PLAYBOOK、安全、权重、支架、互动参数。  
**新增呈现：** 当前 focus、缺口处方、sceneNote、故事墙、渐退——这才是「整个培养系统」的可见性。

## 11. 验收问题（设计是否够深）

家长应能回答：

1. 最近更常练到哪维？哪维在渐退、哪维还要支架？  
2. 系统建议下周补什么？是否已写进下次引导？  
3. 某幅画马良理解成什么（sceneNote）？孩子金句是什么（story）？  
4. 改人设会变语气；改权重/focus 会变练什么——两者不混。

若只能回答「改了一段 system 文案」——系统仍太简单。

## 12. 与配置目标的关系

配置呈现（人设/PLAYBOOK/安全/档案）是 **旋钮**。  
本深化设计是 **传动轴**（缺口→策略→证据→档案）。  
旋钮已齐后，下一优先级是传动轴 P0，否则配置再全也只是「高级记事本」。
