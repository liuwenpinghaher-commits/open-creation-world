# 全量审查报告（最严 · 用户旅程）

> 日期：2026-07-27  
> 触发：用户反馈「没画笔/橡皮、语音为主却大打字框、底栏下叠层看不清」  
> 方法：对照 v3.1 §5.3 UI 线框 + UI 原则 + 真机代码路径（非只跑 test 绿）

## 用户旅程验收（修前）

| 步骤 | 期望（方案） | 修前事实 | 等级 |
|------|--------------|----------|------|
| 打开就能画 | 默认画笔，笔够大 | 未 `setCurrentTool('draw')`；成人工具栏与自研底栏抢位 | **P0** |
| 换橡皮 | 大按钮可见 | **无自研橡皮**；依赖 tldraw 底栏（常被挡住） | **P0** |
| 安静画 | 画布 ≥80%，少挡笔 | 底栏多层 + tldraw Navigation/Toolbar 叠在底部 | **P0** |
| 邀请说话 | **按住说话为主** | 打字 `flex:1` 占主视觉；按住说是小按钮 | **P0** |
| 听回复 | 气泡不挡笔、清晰 | 状态行+气泡+错误+composer 叠高；与 tldraw 底栏重叠 | **P0** |
| 打字兜底 | 次要、失败时可用 | 常驻大输入框，像主路径 | **P0** |
| 家长设置 | 极小入口 | 与发送/新画挤在同一行 | **P1** |
| 禁 debug | 无 phase 英文/技术文案 | 「可喊马良 / browser_fuzzy」常驻 | **P1** |

## 根因

1. **未学旧仓正确范式**：创造世界 `SketchCanvas` 用 `hideUi` + 默认 `draw` + 自研笔/橡皮；本仓保留 tldraw 全 UI。  
2. **底栏 z 轴冲突**：`.app-chrome` `bottom:16` z=400 与 tldraw `DefaultToolbar`/`NavigationPanel` 同区 → 「打字框下面还有东西看不清」。  
3. **产品优先级反了**：方案「语音优先」被实现成「输入框优先」。
